📘 <%:VLAN Guide — click to expand%>

<%:VLAN (Virtual Local Area Network) divides one physical LAN into multiple logical networks. Devices on the same switch can be isolated into separate groups — as if they were on entirely different networks.%>

🛠️ <%:Why use VLAN?%>
  • <%:Security:%> <%:Keep sensitive departments (Finance, HR) separate from the general network.%>
  • <%:Traffic management:%> <%:Reduce broadcast traffic and improve speed.%>
  • <%:Easy management:%> <%:Move a device without reconfiguring its network.%>
  • <%:Cost efficiency:%> <%:No extra switches or routers needed for separate networks.%>
⚙️ <%:How does it work?%>

<%:A normal switch broadcasts to every port. With VLANs configured, the switch groups ports by VLAN ID. A device in VLAN 10 can only talk to other devices in VLAN 10 — even on the same physical switch.%>

🔍 <%:First check: DSA or swconfig?%>

<%:OpenWrt has two switch architectures. The VLAN steps below only apply to DSA.%>

  • <%:If your menu shows%> Network → Switch — <%:your router uses the older swconfig.%>
  • <%:If your menu shows%> Network → Interfaces → Devices <%:with "Bridge VLAN filtering" — your router uses DSA.%>

<%:OpenWrt 21.02 and later (e.g. 23.05) typically use DSA and replace swconfig, but some devices still ship with swconfig. Check before proceeding.%>

<%:Note: some single-port travel routers do not support VLAN filtering at all.%>

📂 <%:Types of VLAN (detailed)%>
1. <%:Port-based VLAN%>

<%:The simplest and most common type. Physical switch ports are grouped into VLAN IDs.%>

<%:How it works:%> <%:Suppose ports 1–5 belong to VLAN 10 (IT) and ports 6–10 belong to VLAN 20 (HR). A computer on port 1 can only reach devices on ports 1–5. It cannot reach anything on ports 6–10.%>

<%:Benefit:%> <%:Simple and predictable. Every port has a fixed VLAN.%>

<%:Limitation:%> <%:If a user moves their computer to a different port, the VLAN changes. This is the main drawback.%>

2. <%:Tagged VLAN (802.1Q)%>

<%:Used when multiple VLANs must share one physical cable — typically between two switches, or between a switch and a router. That shared link is called a "Trunk port".%>

<%:How it works:%> <%:Per IEEE 802.1Q, every packet carries a small tag in its header showing its VLAN ID (e.g. 10 or 20). The receiving switch reads the tag and forwards the packet to the right VLAN.%>

<%:Benefit:%> <%:One cable carries traffic for many VLANs, saving switch ports and cabling.%>

<%:Limitation:%> <%:Both ends must support 802.1Q tagging. Unmanaged switches typically strip tags and break trunk links.%>

3. <%:MAC-based VLAN%>

<%:The VLAN is assigned by the device's MAC address instead of by port.%>

<%:Benefit:%> <%:Whatever port the laptop plugs into, the switch recognizes its MAC address and puts it on the correct VLAN automatically.%>

<%:Limitation:%> <%:Requires managing a MAC-to-VLAN table. Impractical for networks with many devices or BYOD users.%>

4. <%:Protocol-based VLAN%>

<%:The VLAN is assigned based on the network protocol of the traffic — IPv4, IPv6, IPX, and so on. Each protocol travels over its own VLAN.%>

<%:Use case:%> <%:Legacy enterprise networks separating IP traffic from non-IP protocols.%>

<%:Limitation:%> <%:Rarely used today. Modern networks route by subnet instead.%>

💻 <%:OpenWrt Configuration Steps%>

<%:Example: create VLAN 20 for a Guest / IoT network.%>

⚠️ <%:Before you start:%> <%:Connect via a LAN port you will NOT modify. Never apply VLAN changes over Wi-Fi or over the port you are changing — you will lock yourself out.%>
<%:Step 1 — Enable VLAN filtering on the bridge%>
  1. <%:Go to%> Network → Interfaces → Devices.
  2. <%:Find%> br-lan <%:and click%> Configure.
  3. <%:Open the%> Bridge VLAN filtering <%:tab and tick%> Enable VLAN filtering.
<%:Step 2 — Assign ports%>
  1. <%:Click%> Add.
  2. VLAN ID: <%:enter the ID (e.g.%> 20).
  3. Local: <%:tick — attaches the router's CPU to this VLAN.%>
  4. Ports Configuration:
    • <%:Untagged (Access port):%> <%:select%> egress untagged <%:and tick%> PVID.
    • <%:Tagged (Trunk):%> <%:select%> egress tagged.

⚠️ <%:Default VLAN 1:%> <%:When you enable filtering, VLAN 1 covers every port. To fully isolate a port into VLAN 20, you must set that port's VLAN 1 to%> off. <%:Otherwise the port still belongs to VLAN 1.%>

ℹ️ <%:Optional — CPU on VLAN 1:%> <%:If you do not want the router reachable on VLAN 1, set the CPU port's VLAN 1 to%> off <%:as well.%>

<%:Click%> Save.

<%:Step 3 — Create interface and IP%>
  1. <%:Go to%> Interfaces → Add new interface.
  2. Name: <%:e.g.%> GUEST.
  3. Protocol: Static address.
  4. Device: <%:select the VLAN device. Usually%> br-lan.20, <%:but it will match your bridge name (e.g.%> br-guest.20).
  5. <%:Click%> Create interface.
  6. <%:Set an IP block (e.g.%> 192.168.20.1 / 255.255.255.0).
  7. <%:Open the%> DHCP Server <%:tab and click%> Setup DHCP Server.
  8. <%:Verify the DHCP range, lease time, and that the interface is not ignored.%>
<%:Step 3.5 — Test the VLAN before continuing%>
  1. <%:Connect a laptop to an untagged VLAN 20 port.%>
  2. <%:Check its IP — should be in the%> 192.168.20.x <%:range.%>
  3. <%:If it gets%> 192.168.1.x <%:instead, your untagged/PVID settings need fixing.%>

<%:Only after this test passes, proceed to firewall zone configuration.%>

<%:Step 4 — Firewall zone (with DHCP/DNS fix)%>
  1. <%:Inside the interface config, open%> Firewall Settings.
  2. <%:Create a zone named%> guest_zone.
  3. <%:Set%> Input <%:to%> REJECT, Output <%:to%> ACCEPT, Forward <%:to%> REJECT.
  4. <%:In%> Allow forward to destination zones, <%:tick only%> wan. <%:Never tick%> lan.

⚠️ <%:If Input is REJECT, guests get no DHCP/DNS.%> <%:Add two Traffic Rules with these exact fields:%>

  • <%:Rule 1 (DHCP):%> Source zone guest_zone, Destination zone Device (input), Protocol UDP, Destination port 67-68, Action accept.
  • <%:Rule 2 (DNS):%> Source zone guest_zone, Destination zone Device (input), Protocol TCP+UDP, Destination port 53, Action accept.

<%:Without%> Device (input) <%:as the destination zone, the rule will not match traffic addressed to the router itself.%>

<%:Alternatively, set Input to%> ACCEPT <%:— simpler but less secure.%>

<%:Ensure the WAN zone has%> Masquerading <%:and%> MSS clamping <%:enabled.%>

<%:Click%> Save & Apply.

⚠️ <%:Lockout warning:%> <%:Never assign the port you are connected through to a Tagged or different VLAN. You will lock yourself out.%>
📶 <%:Tagging a Wi-Fi SSID to a VLAN%>
⚠️ <%:Do this over a wired LAN connection%> <%:— not the Wi-Fi you are modifying. Otherwise you disconnect yourself mid-configuration.%>

<%:You do not tag the SSID directly. You attach the wireless interface to the VLAN's network interface.%>

<%:Step 1 — Create a new Wi-Fi interface%>
  1. <%:Go to%> Network → Wireless.
  2. <%:Click%> Add <%:next to the radio.%>
  3. Mode: Access Point.
  4. ESSID: <%:e.g.%> My-Guest-WiFi.
  5. <%:Set a password (WPA2-PSK or WPA3-SAE).%>
<%:Step 2 — Attach Wi-Fi to the VLAN interface%>
  1. <%:Before saving, open%> Interface Configuration → Interface Settings.
  2. <%:Untick%> lan.
  3. <%:Tick your VLAN interface (e.g.%> GUEST).
  4. <%:Click%> Save.
<%:Step 3 — Apply and test%>
  1. <%:Click%> Save & Apply.
  2. <%:Connect a phone or laptop to the new Wi-Fi.%>
  3. <%:Check its IP. If it comes from the VLAN block (e.g.%> 192.168.20.X), <%:tagging worked.%>
🛡️ <%:Client Isolation (Guest Wi-Fi security)%>

<%:Prevents devices on the same Guest Wi-Fi from reaching each other. Blocks malware spread between guests.%>

<%:Step 1 — Wi-Fi: isolate clients%>
  1. <%:Go to%> Network → Wireless.
  2. <%:Edit the Guest SSID.%>
  3. <%:Open%> Advanced Settings.
  4. <%:Tick%> Isolate clients.
  5. <%:Click%> Save.
<%:Step 2 — Isolate Ethernet ports (if any)%>

<%:Isolation for Wi-Fi clients is handled by the Wi-Fi setting above. Bridge port isolation applies only to Ethernet ports inside the same bridge.%>

<%:If you have Guest Ethernet ports, isolate them in the Guest bridge (not%> br-lan):

  1. <%:Go to%> Network → Interfaces → Devices.
  2. <%:Configure the guest bridge.%>
  3. <%:Open the%> Bridge ports <%:tab and click the gear next to each guest Ethernet port.%>
  4. <%:Tick%> Isolate.
  5. <%:Click%> Save.
<%:Step 3 — Apply and test%>
  1. <%:Click%> Save & Apply.
  2. <%:Connect two devices to Guest Wi-Fi.%>
  3. <%:From the second device, try%> ping <%:or%> arp -a <%:to the first.%>
  4. <%:A failed ping usually means isolation works. Some devices block ping by their own firewall — check with a real connection instead.%>
📖 <%:Term definitions for new users%>
VLAN ID

<%:A number from 1 to 4094 identifying which virtual network a device belongs to.%>

<%:Reserved values:%> <%:VLAN 0 and VLAN 4095 are reserved. Avoid VLAN 1 for user or guest networks.%>

<%:Analogy:%> <%:Room numbers in a school — Class 5, Class 6, Class 7.%>

<%:Access Port%>

<%:A switch port dedicated to a single VLAN. Anything plugged in joins that VLAN only.%>

<%:Analogy:%> <%:One classroom's door — you enter and you are in that room.%>

<%:Trunk Port%>

<%:A port carrying multiple VLANs over one link. Used for switch-to-switch or switch-to-router connections.%>

<%:Analogy:%> <%:A highway shared by traffic from several cities.%>

<%:Tagged VLAN%>

<%:When multiple VLANs share a trunk, each packet carries a digital tag identifying its VLAN.%>

<%:Analogy:%> <%:Courier parcels labelled Dhaka / Chittagong / Sylhet.%>

<%:Comparison table%>

<%:Term%> <%:Analogy%> <%:Main function%>
VLAN ID <%:Classroom number%> <%:Gives the network a separate identity%>
<%:Access Port%> <%:One classroom door%> <%:Connects a single VLAN device%>
<%:Trunk Port%> <%:School main gate / highway%> <%:Carries multiple VLANs over one cable%>
<%:Tagged VLAN%> <%:Parcel address sticker%> <%:Marks which VLAN a packet belongs to%>
🪵 <%:Inter-VLAN Routing (Router-on-a-Stick)%>

<%:Inter-VLAN routing lets devices on different VLANs (e.g. VLAN 10 and VLAN 20) reach each other, with the router acting as the gateway between them.%>

ℹ️ <%:OpenWrt vs Cisco:%> <%:On OpenWrt, inter-VLAN routing happens automatically through firewall zone forwarding. You do NOT create sub-interfaces like%> gigabitethernet 0/1.10 <%:as you would on Cisco. The Cisco example below is educational only.%>
<%:Why the name "Router-on-a-Stick"?%>

<%:Normally, connecting two separate networks would need two router ports and two cables. This approach uses only one physical cable — a "stick" — between the router and the switch. Inside the router, that one cable is split into multiple virtual sub-interfaces, one per VLAN. Visually, it looks like a router sitting on the end of a single stick.%>

<%:How it works — step by step%>
  1. <%:A PC on VLAN 10 wants to send data to a PC on VLAN 20.%>
  2. <%:The switch sees the destination is in another VLAN. It tags the packet with VLAN 10 and sends it over the trunk port.%>
  3. <%:The router receives the packet on its VLAN 10 sub-interface.%>
  4. <%:The router checks its routing table and decides to send it to VLAN 20.%>
  5. <%:The router strips the old tag and applies a new VLAN 20 tag. It sends the packet back over the same cable.%>
  6. <%:The switch reads the new tag and delivers the packet to the VLAN 20 PC.%>
<%:Cisco configuration example%>

<%:Switch side — make the router-facing port a trunk:%>

Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# switchport trunk encapsulation dot1q
Switch(config-if)# switchport mode trunk
Switch(config-if)# exit

<%:Router side — create sub-interfaces:%>

Router(config)# interface gigabitethernet 0/1
Router(config-if)# no shutdown
Router(config-if)# exit

Router(config)# interface gigabitethernet 0/1.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface gigabitethernet 0/1.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
Router(config-subif)# exit

<%:End devices:%> <%:set their default gateway to the matching sub-interface IP (e.g.%> 192.168.10.1 <%:for VLAN 10,%> 192.168.20.1 <%:for VLAN 20).%>

<%:On older switches you may need%> switchport trunk encapsulation dot1q <%:before%> switchport mode trunk. <%:All referenced VLANs must already exist on the switch.%>

<%:Pros and cons%>
<%:Pros%> <%:Cons%>
<%:Lower cost — one router port, one cable.%> <%:Bandwidth bottleneck — all VLANs share the same cable.%>
<%:Easy setup for small and medium networks.%> <%:Single point of failure — a broken cable or port stops all inter-VLAN traffic.%>
🔥 <%:Zone Forwarding — LAN to Guest (one-way)%>

<%:Allow the LAN to reach the Guest network, but not vice versa.%>

  1. <%:Go to%> Network → Firewall → Zones.
  2. <%:Click%> Edit <%:on the%> lan <%:zone.%>
  3. <%:Scroll to%> Inter-Zone Forwarding.
  4. <%:In%> Allow forward to destination zones, <%:tick%> guest_zone.
  5. <%:Click%> Save & Apply.

⚠️ <%:Never enable Guest → LAN.%> <%:Leaving it disabled keeps the main network protected.%>

🎯 <%:Allow only one Guest device (Traffic Rules)%>

<%:Instead of opening the whole Guest zone, allow only a specific device such as a shared printer.%>

  1. <%:Go to%> Network → Firewall → Traffic Rules.
  2. <%:Click%> Add new forward rule.
  3. Name: <%:e.g.%> Allow-LAN-to-Guest-Printer.
  4. Protocol: TCP.
  5. Source zone: lan.
  6. Destination zone: guest_zone.
  7. Destination IP: <%:the printer's IP (e.g.%> 192.168.20.50).
  8. Destination port: 9100.
  9. Action: accept.
  10. <%:Click%> Save & Apply.
⚠️ <%:Check for conflicts:%> <%:If you already enabled zone-level%> lan → guest_zone, <%:this traffic rule is redundant. Untick the zone-level forward first.%>
📌 <%:Static Lease (IP reservation)%>

<%:If a device's IP changes, firewall rules targeting it stop working. Reserve its IP so it stays fixed.%>

  1. <%:Go to%> Network → DHCP and DNS → Static Leases.
  2. <%:Click%> Add.
  3. Hostname: <%:e.g.%> Guest-Printer.
  4. MAC-Address: <%:pick from the dropdown.%>
  5. IPv4-Address: <%:the fixed IP (must be inside the VLAN's subnet and outside the dynamic DHCP pool, e.g.%> 192.168.20.50).
  6. Lease time: <%:leave empty or set%> infinite.
  7. <%:Click%> Save & Apply.

<%:Pro tip:%> <%:Restart the device (or reconnect it) so it requests a fresh lease and picks up the reserved IP.%>

🛟 <%:Anti-lockout & rollback%>

<%:If a VLAN change locks you out, use these tools.%>

  1. <%:LuCI shows a confirmation countdown after applying network changes. If you lose access, do nothing — after about 90 seconds it reverts automatically.%>
  2. <%:This app has its own safety toggle.%> <%:Safe apply%> <%:above snapshots the network config before every apply, so you can restore with one click.%>
  3. <%:If you get locked out mid-config, connect via serial console or another VLAN and run the restore command.%>

<%:Restore command:%>

cp /etc/easymesh/network.bak /etc/config/network
/etc/init.d/network reload

<%:Note: The path%> /etc/easymesh/network.bak <%:is specific to this app. On a plain OpenWrt system with a manual backup, use your own path (e.g.%> /etc/config/network.bak).

<%:If reload does not restore access, reboot.%>
